# Documentation Guidance

Docs are decision records for humans and coding agents.

- Separate verified facts from assumptions and recommendations.
- Link time-sensitive claims to official sources and include a verification date.
- When product scope changes, update `VISION.md`, the relevant spec, and the roadmap together.
- Visual tokens are canonical in `docs/design.md` and mirrored in `docs/design.html`; keep both synchronized and do not duplicate their values in the PRD.
- Use exact attraction, restaurant, resort, and ticket names in user-facing copy.
- Never describe tentative dining or Lightning Lane choices as reservations.
- Keep open questions explicit. An unknown is safer than an invented Disney rule.
